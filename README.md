# RoutineLog

복약·영양제 알림과 습관 기록을 위한 루틴 앱 (Android, Expo SDK 58). 캘린더 앱과는 별개의 기록용 앱입니다.

## 기능
- **오늘**: 날짜 이동(지난 날 빠뜨린 체크 보충), 진행 링, 시간대별 카드. 복약·영양제는 탭 한 번으로 체크, 습관은 +/−(하루 목표 횟수), 주 N회 습관은 "오늘 했어요". 카드를 길게 누르면 건너뛰기·메모·기록 수정. 체크하면 "되돌리기" 안내
- **기록**: 날짜별 일지(어떤 걸 했는지 메모·값 포함), 루틴 필터·메모 검색·기간, 월 히트맵 달력, 직접 기록 추가/수정/삭제(먹은 시각 수정)
- **루틴**: 복약 / 영양제 / 습관. 스케줄 매일·요일 선택·N일마다·주 N회, 하루 여러 시각(아침·점심·저녁·취침 전 프리셋), 시작/종료일, 하루 목표 횟수·단위, 복제·보관·삭제
- **알림**: 시각마다 로컬 알림(앞으로 14일치를 개별 예약, 체크하면 해당 슬롯 알림·재알림 취소). **방식 선택: 소리 / 진동 / 조용히** (루틴별 또는 앱 기본값), 안 했으면 N분 뒤 재알림, 설정에서 테스트 알림
- **통계**: 연속 달성(streak, 쉬는 날은 이어짐), 이번 주/달/30일 달성률, 복약 순응도와 늦게 먹은 비율, 요일 패턴, 12주 히트맵, 값(km·쪽 …) 주간 합계
- **설정**: 알림 권한, 기본 알림 방식, 정확한 알림(알람 방식), 하루 시작 시각, 백업(JSON)·복원·CSV

## 알림 방식 (Android 채널)
채널은 만든 뒤 소리/진동을 바꿀 수 없어서 방식마다 따로 둡니다: `routine-sound`(소리+진동, 중요도 높음), `routine-vibrate`(소리 없이 진동), `routine-silent`(소리·진동 없이 알림창에만). 앱 시작 시 멱등으로 생성하고, 예약할 때 루틴의 방식(없으면 앱 기본값)에 맞는 채널을 지정합니다. 소리가 기대와 다르면 시스템 알림 설정에서 채널을 확인하세요(시스템에서 바꾼 값이 우선).

## 딥링크 (`routinelog://`)
`/today` · `/log?routine=<id|이름>&date=YYYY-MM-DD` (값이 채워진 기록 추가) · `/add?name=&kind=&times=09:00,21:00&days=1111100&detail=` (값이 채워진 루틴 추가). **저장은 항상 사용자가** 누릅니다(알림 예약이 앱 안에서 이뤄지기 때문).

## 비서 연동
비서 앱(`com.hwetj.assistant`)이 앱을 열지 않고 읽고 체크합니다. 로컬 모듈 `modules/assistant-share` 의 ContentProvider(authority `com.hwetj.routinelog.assistant`)가 같은 SQLite 파일을 직접 엽니다. 호출자 패키지를 검사하고(`com.hwetj.assistant` 만 허용), 메서드는 `query` / `log` / `undo`. 규칙과 SQL 은 [`docs/provider-sql.md`](docs/provider-sql.md), Python 참조 구현과 테스트는 `tests/provider/`. 앱은 포그라운드로 돌아올 때 DB 를 다시 읽고 알림을 재예약합니다.

## 개발
`npm test` (jest, 시간대 3종), `npx tsc --noEmit`, `npx eslint .`, `python3 -m unittest tests.provider.test_provider tests.provider.test_parity`. 빌드는 GitHub Actions(`build-apk.yml`)가 release APK 를 만들어 Releases 에 올립니다.

## 알려진 한계
- 복약 알림은 앱이 한 번도 안 열린 채 14일이 지나면 끊깁니다(앱을 열 때마다 앞으로 14일치를 다시 예약)
- 알림의 "했어요" 버튼은 앱을 앞으로 가져와 기록합니다(백그라운드 처리 아님)
- "하루 시작 시각"을 자정이 아닌 값으로 쓰면, 그 시각보다 이른 복용 시각(예: 01:00)의 "놓침" 판정이 하루 끝(25:00)이 아니라 새벽 1시 기준으로 됩니다
